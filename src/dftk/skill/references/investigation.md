# Investigation loop

Use this loop for multi-step work.

1. **Parse the task** — preserve original question numbering and wording.
2. **Classify each claim** — value, event/time, count, relationship, behavior, attribution, negative, chronology.
3. **Define evidence requirements** — what would actually prove each claim.
4. **Inventory artifacts** — identify structure, source, hash, and relevant sub-artifacts.
5. **Create a DFTK case** when multiple runs/questions benefit from preserved Observations.
6. **Find/describe capabilities** from the highest-priority evidence gap.
7. **Run one purposeful action** with bounded parameters.
8. **Interpret status and evidence** — include warnings/limitations.
9. **Correlate** only with defensible join keys.
10. **Update confidence/gap** in your own task state.
11. **Verify or replan** — choose independent corroboration when it tests a weak link.
12. **Stop** when sufficient, exhausted, unsupported, or blocked.
13. **Report exact answer + provenance**, not a transcript of every attempt.

## Multi-question efficiency
Do not solve each question in isolation if one structured parse can answer several claims. Reuse an Observation rather than rerunning the same capability.

## Failed hypotheses
A failed hypothesis is progress when it rules out a path. Do not hide it if it materially explains why a claim remains unresolved, but do not flood the final answer with every abandoned search.
