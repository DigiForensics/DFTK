# DFTK 3.5.0 release notes

DFTK 3.5 keeps the project boundary introduced in 3.0: DFTK is a deterministic forensic toolkit, not an autonomous Agent. This release closes the provenance-coverage gap, adds network and file-system forensic primitives, and introduces a live-oracle differential test gate so parser regressions can no longer drift silently.

## Provenance auto-wiring

`registry.run()` now stamps a `ProvenanceIndex` for every Observation automatically. Previously only four hand-maintained modules added provenance nodes, so most tools produced evidence with no auditable source chain. Now each evidence is registered as a source artifact with a deterministic `uuid5(source|locator)` id, and the audit ledger de-duplicates evidence hashes. The provenance `version` is sourced from `dftk.__version__` (3.5.0) for both hand-stamped and auto-wired nodes, removing mixed-version chains.

- Reports expose full source lineage via `derived_artifacts`.
- `case_verify` validates the `meta["provenance"]` chain.

## Network forensics

New primitives in `dftk.primitives.network` (~+667 lines):

- `network.pcap_inventory` — packet/byte counts, link type.
- `network.network_flows` — TCP/UDP flow endpoints and durations.
- `network.tcp_reassemble` — deterministic server→client / client→server stream reassembly with sha256 previews.
- `network.tls_inventory` — JA3 / SNI inventory (READ_ONLY).

## File-system, registry & SQLite forensics

New cores under `dftk.core`: `e01` (E01 image), `fat` (FAT filesystem), `fs_backend` (unified fs access), `partition` (partition tables), `hive` / `regf` (registry hive parse + deleted-key recovery), `sqlite_forensic` (WAL/page carving), `path_policy`, `provenance`. Matching primitives: `windows_srum`, `windows_shimcache`, `windows_amcache`, `windows_usn`, `memory_volatility`, `filesystem`, `application_profiles`, `binary_deep`, `case_verify`, `report`.

## Install extras & Dockerfile

- `pip install "dftk[ese]"` — E01/SRUM support (was an undocumented dead-end).
- `pip install "dftk[image]"` — disk-image / partition support.
- `pip install "dftk[credibility]"` — pulls pefile/scapy/dpkt/lief/regipy for the oracle differential gate.
- `pip install "dftk[all]"` — everything.
- New `Dockerfile` unlocks disk-image and SRUM parsing with system libraries.
- `doctor.py` now reports SRUM/E01 optional-dependency availability.

## Live-oracle differential test gate

`tests/corpus_generators.py` + `tests/test_oracle_differential.py` replace frozen golden constants with **executed** independent oracles:

- PE imphash / exports / section count cross-checked against live `pefile`.
- PCAP packet counts and TCP reassembly sha256 cross-checked against live `dpkt`; packets generated by `scapy`.
- Best-effort layer runs the same oracles against real evidence in `examples/demos/output/evidence/` when present (skipped in CI until the corpus is committed).

The full suite is **228 passed** (220 prior + 8 differential). Frozen golden constants remain as a "known-good" guard; the live oracles guard against DFTK silently drifting with its own past values.

## Compatibility

- Base DFTK still has zero mandatory third-party dependencies.
- Existing CLI commands and public `get_registry()` / `run_tool()` integration remain available.
- 3.0/3.3 case-manifest schema and public Observation/Evidence contract preserved.

## Not in this release

- `examples/demos/` real-sample golden corpus is **not** committed here; CI currently skips the real-evidence differential tests. Landing it (Git-LFS or a committed compliant subset) is tracked as a follow-up so the real-evidence gate runs in CI.
